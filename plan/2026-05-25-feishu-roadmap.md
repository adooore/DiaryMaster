# DiaryMaster 飞书渠道 — 后续功能规划

**日期**：2026-05-25  
**用途**：基于当前飞书应用**已开通权限**与代码现状，规划后续可迭代功能。**本文档仅作计划，不代表已排期或已开发。**

**关联文档**：`done-2026-05-25-feishu.md`（开发任务表与 P0/P1 实现记录）

**状态标记**：`待办` | `进行中` | `已完成` | `跳过` | `需补权限`

---

## 1. 规划原则

1. **权限驱动**：只规划应用后台已开通、且与 DiaryMaster（日记 Agent）相关的 IM 能力；未开通的权限标为「需补权限」，不列入近期开发。
2. **配置从简**：设置页仅需 **App ID + App Secret**；事件订阅使用**明文**（关闭加密），不再要求 Verification Token / Encrypt Key。
3. **渠道边界**：飞书渠道保持 `thinking_enabled=false`、`current_file=null`；不推送 Web SSE `step`；危险工具（如 `delete_path`）继续拒绝。
4. **优先闭环**：先完成 F0/F8 端到端联调，再按「单聊体验 → 群聊 @ → 富交互」递进。

## 2. 当前应用已开通权限（用户提供）

| 权限 | 与 DiaryMaster 的相关性 |
| ---- | ----------------------- |
| 读取用户发给智能体的单聊消息 | **核心**：私聊收消息 |
| 以应用的身份发消息 | **核心**：回复用户 |
| 获取单聊、群组消息 | 收群消息、解析上下文 |
| 获取群组中用户 @ 智能体消息 | **群聊 @ 回复** |

| 查看群信息 | 群名/元数据展示、Session 标题 |
| 更新群信息 | 低优先；一般不改群资料 |
| 查看 / 添加 / 取消 Pin 消息 | 可选：Pin 重要回复或用户指令 |
| 查看 / 发送 / 删除消息表情回复 | 可选：「收到」类轻反馈 |
| 更新消息 | 可选：长回复先占位再编辑，替代多条分段 |
| 给多个用户批量发消息 | **跳过**：非日记场景 |
| 发送特定模板系统消息 | **跳过**：系统模板与 Agent 自由文本重复 |
| 订阅智能体进、出群事件 | 可选：入群欢迎 / 离群提示 |
| 创建群 | **跳过**：Agent 主动建群非核心需求 |

**未在列表中出现的常见能力**（当前**不规划**，除非后续补权限）：

- 飞书**互动卡片** / 消息卡片回调
- 图片、文件、语音等**媒体资源下载**（通常需额外 `im:resource` 等 scope）
- 通讯录、日历、审批等非 IM 能力

## 6. 明确不做（即使用户侧「看起来能申请」）

| 项 | 原因 |
| -- | ---- |
| OpenClaw 与 DiaryMaster 同应用双收事件 | 架构冲突，只能一个 URL |
| 飞书渠道推送 Agent `step` / 工具流 | IM 体验差，无 UI 确认 |

| 恢复 Verification Token / Encrypt Key 设置项 | 已简化为明文 + 双凭证 |

## 7. 技术备注（实现时参考）

### 7.1 群聊 @（B1）

- 事件字段：`event.message.chat_type`（`group` / `p2p`）、`mentions` 是否含 bot `open_id`
- 回复 `receive_id_type=chat_id`，`receive_id=chat_id`
- MVP 已用 `chat_id` 发群消息，缺的是**过滤非 @ 消息**

### 7.2 处理中 / 更新消息（B2、C1）

- B2：两条消息（占位 + 结果）→ 实现简单
- C1：需保存 `message_id`，调用「更新应用发送的消息」Open API → 体验更好，开发量中等

### 7.3 Session 绑定（B3）

| 方案 | 优点 | 缺点 |
| ---- | ---- | ---- |
| 每 `open_id` 一个 Session（现状） | 简单 | 群聊多人共用一个 Session 会串话 |
| 每 `chat_id` 一个 Session（群） | 群上下文独立 | 需区分 p2p / group |
| `open_id` + `chat_id` 复合键 | 最隔离 | bind 结构变复杂 |

**建议**：B1 落地时采用 **p2p → open_id 绑定；group → chat_id 绑定**。

### 7.4 事件订阅扩展（B1、D3）

除 `im.message.receive_v1` 外，按需增加：

| 事件 | 阶段 |
| ---- | ---- |
| `im.message.receive_v1` | A（已有） |
| `im.chat.member.bot.added_v1` | D3 |
| `im.chat.member.bot.deleted_v1` | D3（可选） |

### 7.5 文件结构（增量）

```text
backend/channels/feishu/
  dispatch.py      # B1 群 @ 过滤；B2 占位；C3 非文本提示
  client.py        # C1 update_message；C2 reaction
  bind.py          # B3 群/私聊绑定策略
  group.py         # 可选：群信息、mentions 解析（B1/B3）
```
